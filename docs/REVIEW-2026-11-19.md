# Revue de passation E0-E6 (2026-11-19)

Point d'etape impose par les regles de passation, apres E6.

## Etat verifie

- main : E0 a E6 fusionnes (7031f20), 56 tests verts, CI 3 systemes.
- Layout : freecad/cnc_control/core (grbl_protocol, transport, streamer,
  connection, worker), freecad/cnc_control/testing (fake_grbl), tests/core.
- Aucun transport reel touche en test : memoire, socket, pty (virtuels) uniquement.

## Decisions et verdict de revue

| ID | Decision | Verdict |
|----|----------|---------|
| E1-01 | Inspection API FreeCAD 1.1.4 : lien serie impossible depuis le GUI -> worker | Valide |
| E2-01 | Parseur GRBL 1.1 pur Python, tables officielles (CSV gnea) completes pour 1.1 | Valide |
| E3-01 | Faux GRBL injectable + transports virtuels via pair memoire | Valide |

## Limites connues (entree en E7)

1. Pas d'annulation de stream en vol : impossible d'injecter un arret temps reel
   pendant un stream -> indispensable pour l'usinage reel.
2. Pas de timeout de lecture : un lien serie reel muet bloquerait le worker.
3. SerialTransport (pyserial) absent : E7.
4. Thread vs sous-processus : thread suffit tant que le GUI ne gele pas ;
   re-evaluer apres E8.

## Incidents (details dans FAILURES.md)

1. Tampon bytes immuable du faux GRBL : serveur mort, tests bloques 19 min.
2. read_line ne drainait pas son tampon avant d'attendre : reponses
   multi-lignes perdues. Lecon : toujours drainer avant de bloquer.
3. pty canonique avalait les octets sans newline : ICANON desactive.
4. E4 : push messages qui acquittaient une ligne ; ligne ingérable qui
   bloquait run() a jamais.
5. E6 : banniere lue avant que le faux GRBL ne soit demarre (ordre de test).

## Regles qui ont fait leurs preuves (a conserver)

- Blocs bash avec resultat attendu, verifiable ligne par ligne.
- Tests toujours sous timeout ; FAILURES.md a chaque echec repeté.
- D>V trace, transports virtuels uniquement, Ordre de sacrifice documente.

- E8 : fin du coeur. Point d'etape apres E8, puis partie FreeCAD (E9+).
